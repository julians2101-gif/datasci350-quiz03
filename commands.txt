Task 2 - Create the commentator Modelfile

File:
ollama/Modelfile

Explanation:
FROM selects granite4:350m as the base model.
temperature 0.7 controls randomness in responses.
top_p 0.9 limits token sampling.
SYSTEM establishes an excited sports commentator persona.

The three rules require answers to have at most four
sentences, address the user as "sports fans", and admit
uncertainty on air.

Task 3 - Build the commentator model

Command:
ollama create commentator -f ollama/Modelfile

Explanation:
Creates a customized model called commentator using
the Modelfile and the locally downloaded Granite model.

This command does not download anything because the
base model is already stored on my laptop.

Task 4 - Test the commentator model

Command:
ollama run commentator "What does git commit do?"

Explanation:
Tests the commentator's behavior on a technical question.

Response:
Sports fans, welcome to today's sports commentary! Let's dive into the world of Git commits. Git commits are a powerful feature that allows you to track changes to your code. They help you keep your code organized and can be used to make changes and revert to previous versions if needed.

Rule 1 (maximum four sentences): Held - exactly 4 sentences.
Rule 2 (addresses "sports fans"): Held.
Rule 3 (admits uncertainty): Not applicable because the model answered the question.

Command:
ollama run commentator "What is the weather in Atlanta right now?"

Explanation:
Tests whether the model admits uncertainty about live information.

Response:
I'm an AI and I don't have real-time capabilities. I'm here to provide information based on the data I was trained on. I apologize for any confusion.

Rule 1 (maximum four sentences): Held - 3 sentences.
Rule 2 (addresses "sports fans"): Broke - did not address the user as "sports fans".
Rule 3 (admits uncertainty): Held - acknowledged that it lacks real-time capabilities.
